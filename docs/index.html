Every TODObecomes an issue

todo-sync-flow is a GitHub Action that turns TODO, FIXME, HACK and BUG comments into GitHub issues, writes each issue link back into its comment, and closes the issue when the comment is removed.

View on GitHub Quick start
GitHub Action · MIT · 63 languages

From comment to closed issue

The action runs on push and reads the diff. Each new comment goes through the same four steps.

  1. 01

    A comment is pushed

    A new TODO, FIXME, HACK or BUG comment lands in a push.

    // TODO: Add rate limiting
  2. 02

    An issue is created

    The issue title carries the full file path and line number, so you can find the comment from the issue list.

    #42 opened
    path + line in the title
  3. 03

    The URL goes back into the comment

    The action commits the issue URL into the comment, linking code and issue in both directions.

    // TODO: Add rate limiting https://github.com/org/repo/issues/42
  4. 04

    The issue closes when the comment goes

    Delete the line and the action reads the issue number from its URL and closes the issue.

    // TODO: Add rate limiting
    #42 closed

No database. The URL in the comment is the state.

Quick start

One workflow file in the repository you want to track. No server and nothing to host.

.github/workflows/todo-sync.yml 
name: Sync TODOs to issues

on:
  push:
    branches: [main]

jobs:
  sync:
    runs-on: ubuntu-latest
    permissions:
      contents: write  # Turns on write-back: commits issue URLs into TODO lines
      issues: write
    concurrency:
      group: todo-sync-${{ github.ref }}  # queue runs so pushes never race
    steps:
      - uses: actions/checkout@v5
        with:
          fetch-depth: 2  # Required: action needs HEAD~1 to diff against
      - uses: stylusnexus/todo-sync-flow@v1
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}

  1. Add the file

    Save it as .github/workflows/todo-sync.yml and push to main.

  2. Decide on write-back

    contents: write lets the action append each issue URL to its TODO line and commit that, to the pushed branch only, touching only those files. For read-only, use contents: read and set insert_urls: 'false'.

  3. Keep fetch-depth: 2

    The action diffs against the previous commit, so the checkout needs it.

  4. Pick up existing TODOs

    On first install, set full_scan: 'true' to scan every file instead of the latest diff.

Inputs

Set these under with:. Only github_token is required.

InputDefaultWhat it does
github_tokenrequiredA GITHUB_TOKEN or personal access token with issues: write and contents: write.
extra_identifiers'[]'JSON array of extra identifiers to detect, each {name, label, priority?}. Priority defaults to normal.
insert_urls'true'Write-back. Commit the issue URL into each new TODO line, on the triggering branch only. Needs contents: write. Set 'false' for read-only.
close_on_remove'true'Close the linked issue when its comment line is deleted.
assignees''Comma-separated GitHub usernames to assign to created issues.
extra_labels''Comma-separated labels added to every created issue.
milestone''Milestone number to assign to created issues.
full_scan'false'Scan every file, not just the latest diff, and create issues for every unlinked TODO. Useful on first install.

Identifiers

Four come built in. Each one sets the issue label and priority. Add your own with extra_identifiers.

Built in

IdentifierLabelPriority

References

Put references in parentheses after any identifier.

// TODO(@alice): Assign to alice
// FIXME(!performance): Add extra 'performance' label
// HACK(#42): Related to issue #42
// TODO(@alice,!perf,#42): All three combined
  • @userAssigns the issue to that user.
  • !labelAdds that label to the issue.
  • #issueMarks it as related to that issue.
  • a,b,cCombine them with commas.

Custom identifiers

Pass a JSON array. Each entry needs a name and a label; priority is optional and defaults to normal.

Custom identifiers step 
- uses: stylusnexus/todo-sync-flow@v1
  with:
    github_token: ${{ secrets.GITHUB_TOKEN }}
    extra_identifiers: |
      [
        {"name": "SRD-VIOLATION", "label": "compliance", "priority": "high"},
        {"name": "AI-SAFETY",     "label": "security",   "priority": "high"}
      ]

Permissions

The workflow that uses the action needs two scopes.

  • issues: writeTo create and close issues.
  • contents: writeWrite-back mode only. Use contents: read with insert_urls: 'false' for read-only.

Without contents: write, write-back mode stops before creating any issue and says how to fix it. Every run writes a job summary listing what it changed.
